# Release Notes v1.1.58

- Version: `v1.1.58`
- Release Date: `2025-12-26`
- Contributors: `@dharayush7` and community contributors
- Summary: This release introduces new features to improve chat reliability and configuration flexibility, resolves several user-facing issues, and delivers performance and UI/UX enhancements across the client and server. No breaking changes are expected for typical deployments.

## New Features
- Chat reliability improvements for large PDFs with smoother streamed responses over WebSockets.
- Optional database SSL configuration via `CLIENT_DATABASE_SSL_CA` for environments requiring CA verification.
- Enhanced onboarding and environment configuration documentation for faster setup and fewer misconfigurations.
- UI components refinement for forms and inputs, improving accessibility and consistency across pages.

Configuration Changes Required:
- Client: If using SSL for the database, set `CLIENT_DATABASE_SSL_CA` to the CA certificate path.
- Client: Confirm `NEXT_PUBLIC_SERVER_SOCKET_URL` points to your backend (e.g., `http://127.0.0.1:8000`).
- Server: Ensure `VECTOR_STORE_URL`, `DATABASE_URL`, and storage credentials are present and valid.

## Bug Fixes
- CLNT-203: Prevented duplicate messages caused by race conditions during socket reconnects; users should no longer see repeat responses in chat.
- SRV-118: Fixed intermittent upload failures when storage credentials were missing or invalid; the upload flow now fails fast with informative messaging.
- UI-077: Resolved minor theme inconsistencies affecting component variants and skeleton loaders; visual polish is consistent across light/dark themes.
- DOC-142: Corrected parsing behavior for certain mixed-encoding PDFs to reduce empty sections and improve extraction accuracy.

Impact:
- Improved user experience during reconnects and uploads.
- More reliable PDF parsing and consistent UI rendering.

Workarounds Retired:
- Manual page refresh during socket reconnects is no longer needed.
- Upload retries due to silent failures are no longer required; validation errors are surfaced early.

## Improvements
- Performance: Reduced socket reconnect latency and stabilized streaming for lengthy responses.
- Performance: Optimized document processing pipeline and chunking behavior to improve throughput on large PDFs.
- UI/UX: Better input grouping, labels, and tooltip consistency; refined skeletons for loading states.
- Architecture: Consolidated socket event handling and clarified service boundaries to reduce coupling and improve maintainability.

## Known Issues
- Misconfigured `NEXT_PUBLIC_SERVER_SOCKET_URL` will still result in connection failures.
  - Workaround: Set the variable to your backend address (e.g., `http://127.0.0.1:8000`), confirm the server is reachable.
- Degraded answers if the vector store (Qdrant) is offline or misconfigured.
  - Workaround: Verify `VECTOR_STORE_URL` and API key (if required), ensure the service is healthy.
- Initial PostgreSQL connection errors due to invalid credentials or missing database.
  - Workaround: Validate `CLIENT_DATABASE_URL` (client) and `DATABASE_URL` (server); confirm the DB is running and accessible.

Planned Fixes:
- Additional safeguards and diagnostics around socket connectivity and vector store availability in upcoming releases.

## Upgrade Instructions
- Client:
  - Review `client/.env.local`, set `NEXT_PUBLIC_SERVER_SOCKET_URL`, and optionally configure `CLIENT_DATABASE_SSL_CA`.
  - Install dependencies: `npm install`.
  - Start: `npm run dev` or build: `npm run build`.
- Server:
  - Review `server/.env` for storage, DB, and vector store settings.
  - Install dependencies: `pip install -r requirements.txt`.
  - Start: `python -m app.main`.
- Database migrations: None required for this release.
