# Release Notes v1.1.57

- Version: `v1.1.57`
- Release Date: `2025-12-26`
- Summary: This release enhances PDF chat responsiveness, strengthens client–server reliability, and refines environment configuration and documentation. No breaking changes expected for typical setups.

## New Features

- Improved chat responsiveness for large PDFs via more robust streaming behavior over WebSockets.
- Clearer environment setup documentation for client and server to reduce onboarding time.
- Expanded troubleshooting guidance across database, vector store, and storage integrations.

## Improvements

- More resilient client socket reconnect behavior to handle backend restarts with fewer disruptions.
- Authentication guidance refined for Kinde setup and redirect flows.
- Tooling clarity: documented Biome use for lint/format and Prisma tooling for local inspection.
- Root README added covering setup, usage, and development guidelines.

## Bug Fixes

- Fixed occasional duplicate chat messages caused by race conditions during socket sync.
- Resolved inconsistent handling of empty/invalid storage configuration that interrupted uploads.
- Corrected minor UI styling inconsistencies related to theme and component variants.

## Known Issues

- WebSocket failures if `NEXT_PUBLIC_SERVER_SOCKET_URL` is misconfigured.
  - Workaround: Ensure backend is reachable (e.g., `http://localhost:8000`) and the client env matches.
- Degraded answer quality if the vector store (Qdrant) is unavailable.
  - Workaround: Verify `VECTOR_STORE_URL` accessibility and API key requirements.
- Initial PostgreSQL connection failures due to invalid credentials or missing database.
  - Workaround: Validate `CLIENT_DATABASE_URL` (client) and `DATABASE_URL` (server); confirm DB is running.

## Technical Requirements

- Client:
  - Node.js `v20+`
  - Next.js `16`
  - React `19`
  - Biome for lint/format
- Server:
  - Python `3.10+`
  - FastAPI + Uvicorn
  - PostgreSQL (async driver such as `asyncpg`)
  - Qdrant vector store
  - S3-compatible storage (AWS S3 or Cloudflare R2)

## Upgrade / Migration

- Client:
  - Review and update `client/.env.local` if needed.
  - Install dependencies: `npm install`.
  - Run dev: `npm run dev` or build: `npm run build`.
- Server:
  - Review and update `server/.env` for storage, DB, and vector store.
  - Install dependencies: `pip install -r requirements.txt`.
  - Start: `python -m app.main`.
- Database migrations: None required in this release.

## Breaking Changes

- None identified for common deployments.
- If upgrading Node.js/Python to meet minimum versions, validate local dev and CI environments.
