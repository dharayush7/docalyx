# Release Notes v1.1.65

- Version: `v1.1.65`
- Release Date: `2025-12-29`
- Target Environment: `Production`
- Summary: This release focuses on reliability of chat streaming, improved onboarding and configuration, UI/UX polish, and performance optimizations across client and server. No breaking changes for standard deployments.

## New Features

- Syntax-highlighted AI responses in chat for code and structured content.
  - Description: Chat messages render with Markdown and syntax highlighting for better readability.
  - Docs: See `README.md` Usage section.
- Enhanced loader animations for uploads and long-running operations.
  - Description: Lottie-based loaders provide clearer feedback during processing.
  - Screenshots: Add UI screenshots to `/client/public` and link here when available.
- Configurable database SSL CA for client environments.
  - Description: Optional `CLIENT_DATABASE_SSL_CA` enables SSL verification in stricter environments.
  - Config: Set `CLIENT_DATABASE_SSL_CA` in `client/.env.local` when required.
- Improved environment setup documentation and examples.
  - Description: Expanded guidance reduces misconfiguration across socket URL, storage, and vector store.
  - Docs: `README.md` and `release-notes/v1.1.58.md`.

## Bug Fixes

- CLNT-231 (Severity: High) — Duplicate chat messages on reconnect
  - Fix: Addressed race conditions in client–server socket re-sync to prevent duplicate responses.
  - Impact: Eliminates repeated messages after transient disconnects.
  - Workarounds Retired: Manual page refresh on reconnect no longer needed.
- SRV-133 (Severity: High) — Upload failures with invalid/missing storage credentials
  - Fix: Added validation and informative error paths to fail fast and surface configuration issues.
  - Impact: Improves reliability and diagnosability of uploads.
- UI-089 (Severity: Medium) — Theme inconsistency across component variants/skeletons
  - Fix: Standardized styles for light/dark themes and adjusted component variants.
  - Impact: More consistent UI presentation across pages.
- DOC-155 (Severity: Medium) — Mixed-encoding PDF parsing intermittently emitted empty sections
  - Fix: Adjusted parsing and chunking logic to handle edge cases and preserve content.
  - Impact: Higher fidelity in extracted text and improved user responses.

## Improvements

- Performance: Reduced socket reconnect latency and stabilized streaming for lengthy responses.
- Performance: Optimized document processing throughput for large PDFs via improved chunking.
- UI/UX: Consistent labels, input groups, tooltips, and loading skeletons across pages.
- Architecture: Consolidated socket event handling and clarified service boundaries for maintainability.
- Tooling: Clearer Biome lint/format usage and Prisma guidance for local data inspection.

## Known Issues

- Misconfigured `NEXT_PUBLIC_SERVER_SOCKET_URL` causes connection failures.
  - Workaround: Set to your backend (e.g., `http://127.0.0.1:8000`) and confirm reachability.
  - Planned Resolution: Additional diagnostics and automated checks in upcoming releases.
- Degraded answer quality if Qdrant (vector store) is offline/misconfigured.
  - Workaround: Verify `VECTOR_STORE_URL` and API key; ensure service health.
  - Planned Resolution: Better health checks and fallbacks targeted for next release cycle.
- Initial PostgreSQL connection errors due to invalid credentials or missing DB.
  - Workaround: Validate `CLIENT_DATABASE_URL` and `DATABASE_URL`; ensure DB is running.

## Upgrade Instructions

- Prerequisites:
  - Client: Node.js `v20+`, Next.js `16`, React `19`, Biome.
  - Server: Python `3.10+`, FastAPI + Uvicorn, PostgreSQL (e.g., `asyncpg`), Qdrant, S3-compatible storage.
- Steps:
  - Client:
    - Review `client/.env.local` and set `NEXT_PUBLIC_SERVER_SOCKET_URL` (e.g., `http://127.0.0.1:8000`).
    - Optionally set `CLIENT_DATABASE_SSL_CA` for SSL environments.
    - Install dependencies: `npm install`.
    - Start dev: `npm run dev` (or build: `npm run build`).
  - Server:
    - Review `server/.env` for storage, DB, and vector store settings.
    - Install dependencies: `pip install -r requirements.txt`.
    - Start: `python -m app.main`.
  - Migrations: None required for this version.
- Rollback:
  - Revert to previous tag: `git checkout v1.1.58` (or prior known-good tag).
  - Redeploy services with previous configuration.
